# Chromium CDP 启动恢复设计

## 目标

保留采集器专用 Chromium 配置和后台启动方式，同时确保每轮只连接本次启动产生的调试端口。启动或连接失败后不得留下浏览器进程影响下一轮。

## 设计

- 启动前结束仅属于专用 `user-data-dir` 的残留 Chromium，并删除旧 `DevToolsActivePort`。
- 仍使用 macOS `open -g` 后台启动，避免抢占前台焦点。
- 只有新端口文件出现后才连接 Playwright。
- 启动、等待端口、连接或上下文初始化任一阶段失败，都再次清理专用 Chromium 和端口文件。
- 正常关闭后也执行同一清理，确保下一轮从确定状态启动。

不改变携程页面解析、航班筛选、价格排序、数据 schema、定时安排或个人 Chrome 配置。

## 验收

- 自动化测试证明旧端口在启动前被清除。
- 自动化测试证明 CDP 连接失败时专用 Chromium 被清理。
- 原有测试全部通过。
- 现有残留进程被安全清理后，当前 Mac 真实采集能进入航班列表并生成完整组合，结束后无残留进程。
