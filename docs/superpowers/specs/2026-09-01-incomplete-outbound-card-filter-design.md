# 不完整去程卡片过滤设计

## 背景

携程页面中除了可见航班，还可能存在隐藏元素或处于部分渲染状态的 `.flight-item`。当前解析器允许这些元素产生 `flight_no: null`，而去程资格检查只验证日期、时间和中转条件。字段不完整的卡片因此可能进入候选排序，并在比较航班号时触发 `null.localeCompare`，导致整个去程日期扫描失败。

## 目标

去程卡片进入排序和选择前，直接排除最终无法形成完整行程的卡片。不改变现有日期、出发时间、到达软限制、直飞与中转配额、返程筛选及总价排序规则。

## 方案

- 去程资格检查除现有时间和中转条件外，还要求航段关键字段完整：日期、航空公司、航班号、起飞时间、起飞机场、到达时间、到达机场、直飞标记及中转信息。
- 不只依赖 `:visible` 过滤。可见卡片也可能尚未渲染完整，字段完整性才是能否继续采集的业务边界。
- 不把空航班号转换成字符串参与排序。坏卡片必须在排序前消失，避免它被选中后继续产生定位或数据质量问题。
- 不改变 JSON 结构；被过滤的卡片不计入合格去程，也不会生成组合或错误记录。

## 验证

- 新增回归测试，构造时间有效但 `flight_no: null` 的去程卡片，确认它被过滤且其他正常卡片继续排序。
- 保留并运行现有去程时间、直飞/中转配额、完整组合和采集器测试。
- 执行完整测试套件和 JavaScript 语法检查。
- 修复后进行一次真实采集，确认不再出现 `null.localeCompare`，并核对 JSON 组合数量与日志一致。

## 不在范围内

- 不调整携程 DOM 选择器或滚动策略。
- 不修改返程规则、价格口径或历史数据。
- 不为不完整卡片补猜航班号，也不新增重试机制。
