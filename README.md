# flight-monitor

在当前 Mac 的桌面会话中使用可见 Chromium 采集携程返程单程价格，并把最新结果与完整历史发布到 GitHub。

## 运行时间

- 用户登录时尝试一次
- 每天 10:30、14:30、18:30
- 计划时间处于睡眠状态时，唤醒后补跑一次
- 距最近一次采集不足两小时则跳过

Mac 关机、退出登录或没有网络时无法采集；系统不会为了监控主动唤醒或阻止睡眠。采集时 Chromium 在后台打开，不取得当前应用的前台焦点。连接家庭 Wi-Fi `gogogo` 时复用监控专用登录配置；其他网络或无法识别 Wi-Fi 时使用一次性未登录配置。

## 查询范围

- 乌鲁木齐（URC）→ 杭州（HGH）
- 日期：2026-10-08
- 必须在 18:00 及以前抵达杭州
- 保留直飞、经停和通程航班，不记录中转航班
- 经停或通程页面展示停留时间时，停留不超过 120 分钟
- 所有合格航班统一按单程起价排序并写入 JSON

采集器直接读取携程单程列表页，不再查询 9 月 30 日或 10 月 1 日去程，也不再选择去程或记录往返组合。价格是航班卡片显示的最低可售起价；不选择舱位，因此不表述为最终支付价。

## 数据

- [`data/latest.json`](data/latest.json)：本轮状态、所有合格返程航班和最近一次单程成功结果
- [`data/history.json`](data/history.json)：保留旧 schema v1/v2 往返历史，并追加 schema v3 返程单程历史

schema v3 使用 `collection_scope: return_one_way` 和 `price_scope: flight_starting_price`。旧往返价格不与新单程价格计算涨跌，也不能成为 schema v3 的最近成功结果。页面触发访问验证时记录 `captcha`，保留最近一次同口径成功结果，不把旧价格冒充为本轮实时价格。

GitHub 托管 Actions 已证明会触发携程风控，只保留作手动诊断，不承担定时监控。
